# 知序 · 本地学习状态系统

知序 **v0.6.1** 是面向长期备考的本地学习管理工具，提供知识树、学习日志、复测与复习安排、AI 录入、学习总结和跨章节分轮评估。记录保存在本机 SQLite 中。

## 使用

克隆仓库后，在项目根目录运行以下命令。需要 Node.js 22+ 和 pnpm 11，依赖版本已锁定。

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

打开 `http://127.0.0.1:4318`，首次使用会创建本地数据库。开发时可以运行 `pnpm dev`。本地知识树、日志和复习可离线使用。AI 录入通过本机 Codex 的 ChatGPT 登录调用模型，需要网络和账户可用额度，无需 API Key。

Windows 上安装依赖后，也可双击 **启动知序.cmd** 构建并启动服务，再用 **停止知序.cmd** 停止服务。服务日志位于 `data/server.log` 与 `data/server.err`。

## 项目结构

| 目录 | 内容 |
| --- | --- |
| `src/app/` | 页面与 API 路由 |
| `src/features/` | 知识树、学习、录入、总结和分轮评估界面 |
| `src/server/` | 学习记录、导入确认、数据库和备份服务 |
| `src/lib/` | 共享数据类型、证据校验和日期规则 |
| `drizzle/` | 按版本执行的 SQLite 迁移 |
| `scripts/`、`tests/` | 数据库命令、演示数据和自动化测试 |

## 现在可以做什么

- 创建、编辑、归档科目、章节和知识点；归档父级时连同子级一起归档。
- 按科目、章节、等级和关键词查看知识树；切换到归档记录查看历史。
- 建档时选择暂不评估或 A～D 自评；E 必须有延迟复测证据，当前不能手动创建。
- 分开记录学习进度、重要性、掌握状态及自评来源。
- 查看知识点详情和追加式历史，手动编辑/粘贴学习摘要。
- 编辑知识点后提示旧摘要可能过期；摘要写入不改变掌握等级。
- 查看真实数据概览，导出全量 JSON，创建并恢复 SQLite 快照。

新增：学习日志关联多个知识点，用时只计一次；结构化复测保留作答、提示、独立性和题型；错误先保留待补充证据，订正后等待复测，独立通过才可确认解决；等级变更需显式确认并保留依据。作废保留原记录与原因，检查后续依赖。

新增 P3：手动学习/复习/抽查任务，需确认的日期建议，任务改期与取消，从任务记录实际日志或复测、同事务完成旧任务并安排下一次；完成记录可撤销，原依据保留于时间线。首页显示到期清单、今日用时、待复测错误和最近等级变化。

新增 v0.4：粘贴学习进度，或上传 UTF-8 TXT / Markdown、PNG / JPEG / WebP 图片；GPT 按所选科目匹配已有知识点、提出新章节与知识点、整理摘要和学习进度。核对原文与归属，可编辑摘要、排除项目，再一次确认保存。时间及用时仅在本人补充实际情况后记录。原文、目录快照、草稿和确认结果进入本地数据库，支持失败重试、历史查阅与完整备份。

**尚未实现**：PDF / Word 直接解析，AI 自动判定复测、掌握等级或错误解决，复杂自适应调度。P4 的连续真实使用验收仍需开展。详见 [AI 录入使用说明](./AI录入使用说明.md)。

原文中明确写出的建议等级、自评等级或评估等级会带入逐项草稿，可修改；确认后 A–E 标记为用户自评，“尚未评估”对应暂未评估，不生成复测通过。等级菜单只提供“暂未评估”和 A–E，新知识点未确认时直接暂未评估；已有知识点无新等级时显示并保留当前等级，需要改回未知时选择“暂未评估”。旧版已保存记录可在整理历史点“补充原文等级”，核对当前状态后只补充等级，不重复保存学习内容与用时，原文与原确认稿保留。

单个等级摘录无法核对时，不再丢弃整份整理：能唯一对应的原文标签优先带入，无法明确对应的等级留空并提示，学习内容保留为待确认草稿。同段整体与分项等级不同，不自动将整体等级套给分项。学习摘录真实性、目录范围、格式校验和保存前的版本检查仍然保留。

归档记录当前仅支持查看，恢复整个数据库可回到归档前的备份；尚未提供单条取消归档。

## 数据位置和备份

- 正式库：`data/study.sqlite`，服务端 SQLite，非浏览器缓存。
- 快照：`backups/`。运行中请用页面“创建并下载备份”或备份命令，不要只复制主数据库文件而忽略 WAL。
- 迁移前备份：已有数据库新增迁移时保存在数据库同级 `migration-backups/`。
- 配置：按需复制 `.env.example` 为 `.env`。`DATABASE_PATH` 是数据库路径，`APP_TIMEZONE` 默认为 Asia/Shanghai，页面使用本地日历，数据库时间使用 UTC。
- 不要将正式数据库、快照、环境文件提交到 Git。

```powershell
pnpm db:backup
# 恢复前先停止应用。工具会拒绝覆盖仍在运行的数据库。
pnpm db:restore "D:\path\backup.sqlite"
```

恢复先验证迁移哈希、数据库完整性及外键，再备份当前库并替换。旧数据库快照留在 `study.sqlite.before-restore-时间戳.sqlite`。恢复工具只接受与当前应用迁移版本完全一致的快照；任意 JSON 合并导入尚未实现。

浏览器备份按钮会在 `backups/` 留副本，并尝试下载。某些内置浏览器可能不显示下载事件；这时可直接从 `backups/` 取走生成文件。页面会显示生成结果。

## 实现和后续扩展

- Next.js App Router，React，TypeScript，Tailwind CSS，shadcn 风格基础 Button，Drizzle 查询与事务，better-sqlite3。
- P0 将已审核 DDL 直接纳入版本化 SQL 迁移，以保留 STRICT、复合外键和触发器。**当前 SQL 迁移是数据库结构来源，`schema.ts` 是 P0/P1 的 ORM 映射，不可用于 schema push 或生成覆盖全库的迁移。** 学习证据表目前使用参数化 SQL；后续补齐其余表映射并验证差异后，再启用 Drizzle Kit 生成；本版不暴露生成命令。
- `0002_catalog_safety.sql` 补充科目/章节版本号，以及 `_command_receipts`、`_catalog_events` 两张基础设施表；原十张业务表保持语义稳定。
- `_migrations` 校验历史迁移哈希，禁止在已有库上静默修改迁移。业务写入经 `src/server/catalog.ts` 、`src/server/learning.ts` 和 `src/server/tasks.ts` 的事务服务。`0003_ai_imports.sql` 新增 `_ai_imports` 基础设施表，保存不可改写的原文与目录快照。`0004_self_reported_levels.sql` 保留知识点字段和全部数据，放宽自评 E 的旧约束；升级前自动备份，事务提交前检查外键。`src/server/imports.ts` 确认时复用上述服务，在同一事务中保存选中的项目与可选日志。
- 请求以 `commandId` 幂等；主实体 ID 保持稳定。编辑携带 `expectedVersion`，过期更新返回 409。初始自评只在建档时开放。
- 科目/章节修改审计保存在 `_catalog_events`，知识点历史保存在 `knowledge_events`；本版知识点时间线可见，目录审计随 JSON 导出。
- 当前 HTTP 接口：GET `/api/catalog`、POST `/api/commands`、POST `/api/learning`、POST `/api/tasks`、GET/POST `/api/imports`、GET `/api/imports/account`、GET `/api/imports/[id]` 及其 `/source` 图片入口、GET `/api/export`、POST `/api/backup`、GET `/api/health`。写入口校验 JSON 和 Origin，未知字段拒绝。
- 默认只监听 127.0.0.1，无跨设备同步，不应公开暴露到互联网。AI 调用仅在点击整理/重试时发生，只发送本次原文/图片和所选科目的活动目录，不发送全量历史或数据库。Codex 处理既有登录凭据，知序不读取 auth.json、浏览器 Cookie 或密码。启用只读沙箱、临时会话，并关闭 shell、插件、记忆等工具；检测到工具调用会停止该次整理。

参考：[Next.js 安装与构建](https://nextjs.org/docs/app/getting-started/installation)、[Drizzle SQLite](https://orm.drizzle.team/docs/get-started/sqlite-new)、[pnpm 构建脚本配置](https://github.com/pnpm/pnpm.io/blob/main/blog/releases/11.0.md)。

## 复测和等级规则

先在知识树建档，再进入学习日志记录一次实际学习，或在知识点详情记录复测。错误页可补充订正和发起针对性复测。

- 未知证据不会当成通过；“独立通过”要求独立完成、提示 0 次、未看答案。
- “调整等级”分为手动自评与复测确认，默认手动自评。自评可直接选择 A–E、跨级上调或下调，必须填写原因；保存后明确标记“用户自评”，不生成测试或通过记录。
- 仅提到、尚未介绍或无法判断的知识点，可选择“暂未评估”。新建知识点默认采用该状态；已有等级可通过手动自评改回暂未评估，保留学习进度和全部旧证据。暂未评估单独显示与筛选，不归入 A–E 等级分布；尚未介绍的内容可另将学习进度设为“未开始”。
- 复测确认必须关联有效测试，可跨级调整；上调或重新确认 C 需要典型题独立通过，D 需要新变式或迁移题独立通过且能解释。
- 复测确认 E 需要当前已达到 D 或 E、两个不同日期的合格复测，最新一次距此前测试或学习/复习至少 7 个完整日，期间无失败或部分通过，且无未解决错误。自评 E 仍标记为用户自评。
- 复测确认方式的降级也需要有效证据与原因。填写订正不会直接解决错误；复测结果不会未经确认自动升级。复测表单中的可选等级确认固定采用复测证据。
- 两种方式的调整前后等级、来源、原因均写入历史；切换为自评不会删除此前复测与证据历史。
- 补录历史不会自动重新计算已经确认的历史等级。学习日志按应用时区记录，同次跨日学习需拆分。
- 日志和复测不覆盖原事实；录错时用作废功能，保留原因。当前等级依赖的证据不能直接作废。

## 学习总结

进入左侧“学习总结”（`/summaries`），选择日期、科目或章节，点击“生成事实汇总”。日期可留空，支持今天、近 7 天、近 30 天和全部时间，也可以只按章节总结。

- 所选时段按实际发生时间与应用时区统计，包含起止两天；作废记录不计入有效用时与测试。多知识点日志用时只计一次，跨章节日志展示整条时间并提示无法拆分。
- AI 录入新增可核对的学习日期，文字中明确标注“学习日期：2026年10月10日”等格式会自动带入；无法识别或图片内容请核对补填。日期可与内容一起确认，用时未统计时无需编造起止时间。旧版已确认内容也会从原文读取明确日期，按学习日期而非上传日期进入总结；未登记用时单独提示，不当作零分钟学习。已有精确日志的录入不再重复计数。
- 页面和 Markdown 导出按日期从新到旧整理，每个日期标题下只放当天学习内容与复测。旧摘要保留在历史，不重复算入当天；无法可靠分离的编辑内容展示本次原文摘录。GPT 当日观察也按依据日期分组，跨日比较和当前状态单列为整体观察。
- 当前知识点、摘要、学习进度、等级依据、错误和待办单独展示，标明截至生成时，不当作所选时段的期末状态。暂未评估、用户自评和复测确认继续区分，归档记录可回看。
- “用 GPT 总结”使用现有 ChatGPT 账户，只发送此范围的快照；返回可编辑草稿与依据引用，不修改任何学习记录，不生成通过、解决错误或完成任务。事实汇总之后数据有变化，需重新汇总再调用 GPT。
- 事实汇总和当前编辑的草稿可复制或导出 Markdown。草稿不自动存入数据库，离开或刷新页面前请导出。相同快照短时间重复请求会复用结果；较大范围请缩短日期或按章节调用 GPT。

## 每天使用与复习安排

1. 在知识树建档，录入最近一次实际学习或复测。
2. 打开“复习安排”：确认合适的规则建议，或手动选择学习、复习复测、抽查类型及日期。每点最多一项待处理任务。
3. 每天从“今日待办”进入对应活动。学习任务关联实际 LEARN 日志；复习/抽查任务关联实际测试，仅阅读不算完成测试任务。失败或尚未判定也可完成一次测试活动，其实际结果不会被改成通过。
4. 保存时可选择“下一次安排”：按规则确认或手动选日期。测试、错误、等级确认、完成旧任务和下一任务一起保存，任一检查失败都不保存部分内容。
5. 已记录的活动可通过“关联已有记录”完成任务，限同点、有效且在任务创建之后发生的记录（输入时间以分钟为精度）。同一记录不能重复完成同点的另一任务。
6. 录错完成依据时，在完成历史中“撤销完成”；若已有下一任务先取消它。撤销不回滚等级或错误解决状态，这些须在各自入口明确修正，原依据仍在时间线。

日期建议 `review-v1`：B +2、C +5、D +14、E +30 天抽查，以最新有效 LEARN/REVIEW 结束或测试时间的本地日期为基准。最新活动为测试时，FAIL/PARTIAL 或依赖提示/答案的 PASS 优先建议 +1 天；独立性证据未知时不生成日期。A 或无活动日期时请手动安排。已明确标记疑似遗忘时建议今天复测。

以上是产品初始规则，不是测得的记忆规律。建议需要确认；补录旧事实只会将过期建议预填为今天，不会替换已有任务。改期后当前任务显示本次改期原因，原原因与日期保留于时间线。首页依次按原定日期、近 14 个本地日期错误次数、未解决错误、遗忘标记和重要性排序；首页展示前 6 项，全部任务在复习页。

关闭服务后不运行后台排程或通知。打开/刷新页面时计算今天的到期任务。复测耗时需通过关联日志记录，不凭测试数量推算分钟；归档历史日志仍计入真实用时，作废日志不计入。

## v0.5.5 第一轮录入优化（2026-10-18）

- 支持文末集中等级清单。同名且唯一的等级进入草稿；名称不一致时展示 GPT 对应候选或完整原文清单，由本人选择归属。历史记录也可以通过“补充原文等级”核对，原始确认稿保留。
- 日期线索区分学习日期、记录日期、对话日期。跨日保留两端候选，不把对话跨度计算为学习时长。实际学习日期仍需核对，一次录入目前保存一个学习日期，多天内容请分次录入。
- GPT 可为新录入生成“待复测建议＋原文依据”，默认不创建任务。本人勾选、选择日期并确认保存后进入复习安排；任务不意味着复测通过，也不会自动提升等级。
- 原有正式记录不批量改写。已有记录的日期与复测任务本轮不自动补建。

## v0.5.6 按章节录入（2026-10-24）

AI 录入新增“整理范围”：全部章节、指定已有章节、新章节。科目总知识点超过300时，选择本次学习的章节继续录入；300是单次发送目录的上限，不是科目容量上限。选定已有章节后，只匹配及新增该范围内的知识点。新章节入口用于尚未建立目录的章节，已有章节请直接选择。


## v0.5.7 整理历史折叠（2026-10-24）

整理历史按本地录入日期分组，默认展开最近一天（从链接直接打开的记录所在日期也会展开），每组显示条数。可单独展开日期，或使用全部收起／展开全部。侧栏内滚动，文件名缩略并可悬停查看完整名称；记录仍可点击回看。


## v0.5.8 自动识别章节（2026-10-24）

整理范围默认“自动识别章节”。原文开头明确写明例如“依据：第七章课件7.1，第3～5页”时，自动匹配已有第七章（支持第7章等章号写法）；尚无目录时，草稿自动填为“第七章”，确认保存时共用创建一次。不会将模块名称代替章号。手动选择“新章节”时也会采用明确章节依据并复用已存在章节。

跨章节、章号冲突或未明确标注时不强行判断，仍可手动选章；前置、后续计划及正文中的章号引用不用于识别当前章节。历史确认稿与既有数据保持原样。


## v0.5.9 总结草稿直接导出（2026-10-24）

## v0.6.0 跨章节的分轮综合评估

进入左侧“分轮评估”（`/rounds`），创建第二轮或后续轮次，填写整体主线。创建时在本地冻结已有知识点、摘要和等级；不改写原文历史，不把创建时快照追溯当成第一轮结束当天。

上传整段 TXT/Markdown 或粘贴跨章节学习记录。只有勾选并点击“用 GPT 整理综合记录”才会将本次原文及本科目的知识点名称、编号发送给 OpenAI GPT；第一轮完整笔记与冻结快照不随该请求外发。先生成可编辑草稿，再由本人确认保存。

- 记录单位是综合任务或问题，一条可关联多个章节、多个知识点。同一知识点也可出现在不同任务里；无需重复新建知识点。无法可靠匹配时允许暂不关联，整体记录仍保留。
- 分别保存首次作答、实际提示、订正、尚待验证及原文建议等级。提示后完成不当作独立通过；“本轮未测”不清除以前表现；原文含提示的 C 只是该轮建议，不直接替换系统 C 或当前等级。
- 原有等级、摘要、复测、错误、任务均保留。综合评估单独追加，不伪造正式通过、错误解决或任务完成。已保存评估及原文保留，可继续追加后续任务。
- 整体主线和来源保留在轮次页面，任务按实际学习日期回看；每项可展开查看此前快照与本轮表现。知识点详情也能看到关联的分轮任务。日期未知单列，不使用上传时间替代。
- 本轮评估、整体主线与相关知识点的此前快照可导出 Markdown。已确认的综合任务同时进入学习总结，按任务计数；按章查看时保留跨章上下文，不把整项表现分摊到各章。
- 有明确日期且实际发生的分轮学习参与复习日期建议与 E 级无练习间隔校验；“本轮未测”不算练习，不改变原等级。只有日期、没有准确时刻时，不编造学习时间，延迟间隔保守按该日结束后计算。
- 新增 `0005_study_rounds.sql`：`study_rounds`、`round_review_records`、`round_review_points` 三张业务表，以及 `_round_imports` 原文/草稿历史表。旧十张业务表不改写，迁移前自动备份；JSON/SQLite 备份含新增数据。
